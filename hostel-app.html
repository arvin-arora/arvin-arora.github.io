Simulated walkthrough of the real check-in pipeline — recreated in hand-written CSS/JS for this site, not actual app screenshots. The real app runs on React Native.

What it is

A hostel attendance system built end-to-end — mobile app plus its own backend. Marking yourself present only works if you pass every check: you’re physically inside the hostel, on the hostel network, on your own registered device, and it’s really your live face in front of the camera.

React NativeTypeScriptML KitGeofencingOwn backend

How a check-in flows through the system

  1. Check-in request

    The app sends the device identity, a live face capture, the GPS fix and network info to the backend.

    REQUEST
  2. Device attestation

    Server-side check that the request comes from the student’s own registered device — one account, one phone.

    GATE 1
  3. Location & network gates

    GPS must land inside the hostel geofence, the Wi-Fi subnet must match the hostel network, and mock-location (GPS spoofing) is detected and rejected.

    GATE 2
  4. Face verification

    ML Kit runs live face verification with liveness detection — a photo of a photo doesn’t pass.

    GATE 3
  5. Attendance recorded

    Only after every gate passes is the attendance written and synced to the admin dashboard.

    WRITE
  6. Reports & alerts

    Admins get PDF and Google Sheets exports, plus scheduled absentee alerts — no manual chasing.

    ADMIN
